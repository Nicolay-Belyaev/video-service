# Video Service

Go-сервис транслирует RTSP/H264 через WebRTC. Фронт на Vue находится в `front/`.

## Конфигурация

Пример формата — `cameras.example.json`. Создайте приватный `cameras.json`
на его основе, задайте адреса и учётные данные камер, ограничьте доступ к файлу
(`chmod 600 cameras.json`). `cameras.json`, `cameras.local.json` и `.env` исключены
из Git. Если используете другое имя, добавьте его в исключения самостоятельно.
Никогда не помещайте конфиг в `front/` или `front/dist/`.

У камеры обязательны положительный уникальный `id`, `name` и непустой `streams`.
У потока обязательны уникальный внутри камеры `id` (буквы, цифры, `_`, `-`),
`label` и `url` со схемой `rtsp` или `rtsps`. Спецсимволы в логине и пароле
нужно URL-кодировать. Разрешение в `label` задаётся вручную.
Пустой каталог `{ "cameras": [] }` допустим.

## Запуск

Нужны Go из `go.mod` и Node.js для фронта. Из корня репозитория:

```sh
npm ci --prefix front
npm run build --prefix front
go run ./cmd/video-server -config cameras.json -listen :80 -probe-timeout 5s
```

При ошибке конфигурации процесс завершается. Перед запуском HTTP сервер проверяет
потоки с параллелизмом до 4 и таймаутом на каждый поток. Проверка выполняет
RTSP DESCRIBE с авторизацией и проверяет наличие H264 в SDP. Она не запускает PLAY
и не гарантирует получение кадров. Недоступный поток не препятствует запуску.

Путь `front/dist` определяется относительно рабочей директории. При поставке
бинарника доставляйте сборку фронта вместе с ним, а конфиг — отдельно.
Для разработки фронта см. `front/README.md`.

## HTTP API

`GET /cameras` возвращает публичный каталог:

```json
{
  "cameras": [
    {
      "id": 1,
      "name": "Вход",
      "available": true,
      "qualities": [
        { "id": "low", "label": "720p", "available": true },
        { "id": "high", "label": "4K", "available": false }
      ]
    }
  ]
}
```

Количество камер — длина массива. Камеры отсортированы по ID, качества сохраняют
порядок конфига. URL, логины и пароли не входят в ответ. `available` — снимок
стартовой проверки; у камеры это наличие хотя бы одного доступного потока.
Периодического мониторинга пока нет. Негативный результат не блокирует выбор
на фронте и новую попытку подключения на бэкенде.

`POST /cameras/{id}/webrtc/{quality}` принимает WebRTC offer и возвращает answer.
`quality` — идентификатор потока из конфига, например `low`, `high`, `medium`.

## Проверки

```sh
go test ./...
npm test --prefix front
npm run build --prefix front
```

Go-тесты проверяют валидацию конфига, публичный каталог, RTSP DESCRIBE с локальным
тестовым сервером, таймаут проверки и жизненный цикл потоков. Реальные камеры
для этих тестов не нужны.
