# Фронт Video Service

Vue 3 и Vite. Видеоплеер и WebRTC используют штатные API браузера.

## Разработка

Нужен Node.js 22.12+ (ветка 22 LTS) и запущенный Go-сервис на порту 80.

Из каталога `front`:

```sh
npm ci
npm run dev
```

Откройте адрес, напечатанный Vite (обычно http://localhost:5173).
Открытие `index.html` через `file://` не поддерживается.
Прокси `/cameras` настроен в `vite.config.js` на `http://127.0.0.1:80`.

## Сборка

Из каталога `front`:

```sh
npm run build
```

Из корня репозитория:

```sh
go run ./cmd/video-server
```

Go отдаёт `front/dist` и API с одного адреса. Запускайте сервер из корня
репозитория и доставляйте каталог `front/dist` вместе с бинарником.
После изменения фронта повторите сборку.

`npm run preview` позволяет проверить сборку отдельно; API также проксируется
в Go-сервис на порту 80.

## Код и модель камеры

- `src/models/camera.js` — загрузка публичного каталога `{ cameras: [...] }`.
  Камера содержит `{ id, name, available, qualities }`, качество — `{ id, label, available }`.
  Имена и качества полностью задаёт бэкенд, RTSP-адреса и секреты фронт не получает.
- `src/App.vue` — загрузка каталога и сетка плееров: один компонент на каждую камеру.
- `src/components/CameraPlayer.vue` — отображение камеры и переключение качества по fullscreen.
- `src/services/webrtc.js` — одна попытка подключения и освобождение ресурсов.
- `src/services/retryConnection.js` — политика повторных подключений.

`available` — результат стартовой проверки. Первым выбирается доступный поток,
но отрицательный результат не запрещает подключение: камера могла включиться позже.

Плееры изначально не подключены. Нажатие на область конкретного плеера запускает
только его поток; остальные камеры остаются неактивными. Кнопка поверх видео
поддерживает мышь и клавиатуру, после запуска доступны нативные controls браузера.
Ручного выбора качества нет: в сетке используется `low` (720p), в полноэкранном
режиме — `high` (4K). Кнопка «На весь экран» разворачивает контейнер плеера через
Fullscreen API. Событие `fullscreenchange` также обрабатывает штатное разворачивание
видео и выход через Esc. При выходе возвращается `low`. Если нужного качества нет,
используется `low` или первый поток из каталога. Неактивные камеры не запускаются.
Переключение создаёт новое WebRTC-соединение, поэтому возможна короткая пауза.

После ошибки подключения или обрыва соединения
он делает максимум 3 дополнительные попытки, каждую через 3 секунды после ошибки.
Одна попытка ограничена 30 секундами. Успешное подключение сбрасывает счётчик;
смена качества активного плеера отменяет его прежнюю сессию и запускает новый цикл.
После исчерпания попыток остаётся сообщение об ошибке и снова появляется область запуска. Политика ретраев относится
к видеопотоку; ошибка загрузки списка камер отображается отдельно.

Проверка политики ретраев: `npm test` из каталога `front`.
